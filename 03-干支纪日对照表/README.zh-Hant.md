# A3 · 干支紀日對照表（1900—2052）

**[简体中文](README.zh.md) ｜ 繁體中文 ｜ [English](README.md) ｜ [日本語](README.ja.md) ｜ [한국어](README.ko.md)**

## 這是什麼

公元 **1900-01-01 至 2052-12-31** 共 **55,883 天**的逐日干支數據，並標出每一天所屬的**旬**、**所在節氣**與**節氣月（月建）**。

## 干支紀日為什麼特殊

年柱有立春分界、月柱有節氣分界、時柱有十二時辰——都有規律可循。**唯獨日柱，沒有簡單的公式**：公曆有閏年與大小月，而干支紀日是**連續不斷的六十日循環**，兩者節奏不同。

正因如此，干支紀日自商代以來兩千餘年從未間斷，是**世界上連續使用最長的紀日體系**。它也因此可以「反過來」當作一個精確的日計數器——**只要確定一個錨點日，全序列即唯一確定**。

## 字段

| 字段 | 含義 |
|:---|:---|
| `date` | 公曆日期 `YYYY-MM-DD` |
| `year` / `month` / `day` | 年月日分量 |
| `weekday` | 星期，**1＝週一 … 7＝週日**（ISO 8601） |
| `jdn` | 儒略日數（整數，對應當日正午） |
| `ganzhi_day` | 日干支，如「甲子」 |
| `ganzhi_index_1_60` | 干支序號，**1＝甲子 … 60＝癸亥** |
| `xun` | 所在旬，如「甲子旬」 |
| `solar_term` | 該日所在的節氣（最近一個已交的節氣） |
| `solar_term_month_branch` | 節氣月（月建）地支，按十二**節**劃分 |
| `next_term` / `next_term_datetime` | 下一個節氣的名稱與交節時刻（北京時間） |

**關於 `solar_term_month_branch`**：僅按十二**節**（立春、驚蟄、清明、立夏、芒種、小暑、立秋、白露、寒露、立冬、大雪、小寒）劃分，立春起寅月。**不涉及年干、不涉五虎遁等任何推演**——它只是「以節氣劃分的月份」這一曆法結構本身。

## 定序錨點

**1949-10-01 ＝ 甲子日。**

來源三源一致：百度百科「甲子日」詞條明載「中華人民共和國成立日（1949年10月1日）即為甲子日」；多個萬年曆站查詢結果一致；常見八字教學教例亦以該日為甲子日。

選它作錨點的理由：位於現代、**不涉及任何曆法換算歧義**。

### 逐條說明

**1. 古籍錨點自洽——這是本表最強的一處驗證。**

《春秋》隱公三年「**二月己巳，日有食之**」是中國典籍中第一次明確記載日期的日食記載。其儒略曆前推日期為**公元前 720 年 2 月 22 日**，本表獨立推算得 **己巳**，與文獻完全吻合。

這個錨點與定序錨點相隔 **2,669 年**，兩者自洽，說明「六十日循環自春秋以來連續未斷」這一假設成立。

> ⚠ **復算時務必注意紀年口徑**：公元前 720 年對應**天文紀年 −719**（公元前 1 年＝天文紀年 0，無公元 0 年）。若按 −720 計算，日期整體偏 **366 天**、**干支差 6 位**——日干支由 **己巳** 變為 **癸亥**，從而誤判「古籍與推算不符」。**這是一處極易踩的坑。**

**2. 有一條來源有誤，已如實標註。**

公開材料中「1965-12-22 為甲子日」之說，本表推算為**庚戌**。1965 年 12 月內並無甲子日（該月最近的一個甲子在 1966-01-05）。**本表未因該條調整錨點**——4 個現代錨點中 4 個一致，且古籍錨點自洽，足以支持定序錨點無誤。

## 曆法切換

1582-10-15 起用格里高利曆，之前用儒略曆前推。**本數據集覆蓋 1900 年以後，不涉及該切換**；生成器已實現該規則，便於擴展到更早年份。

## 與 A1 的關係

`solar_term` 字段由 **A1 二十四節氣交節時刻數據集**聯結而來。**使用本表時建議同時引用 A1**，因為節氣邊界的精度直接決定 `solar_term` 與 `solar_term_month_branch` 的正確性。

**邊界處理（一處易錯點）**：本表首 5 天（1900-01-01 至 01-05）在 1900 年小寒之前，其所在節氣應為**1899 年的冬至**。因此生成時除 A1 主表外，還須讀入 A1 的 `data/preceding_boundary.csv`——否則這 5 天會被誤歸到 1900 年小寒、月建被誤標為「丑」（正確為「子」）。
