# A3 · 干支紀日の対照表（1900—2052）

**[简体中文](README.zh.md) ｜ [繁體中文](README.zh-Hant.md) ｜ [English](README.md) ｜ 日本語 ｜ [한국어](README.ko.md)**

## これは何か

西暦 **1900-01-01 から 2052-12-31** までの **55,883 日**について、日ごとの干支を示し、あわせて各日の属する**旬**、**属する節気**、**節気月（月建）**を記す。

## 干支紀日はなぜ特別か

年柱には立春の分界があり、月柱には節気の分界があり、時柱には十二時辰がある——いずれも規則でたどれる。**ただ日柱だけは、簡単な公式が無い**：太陽暦には閏年と大の月・小の月があり、干支紀日は**途切れない六十日の循環**であって、両者の歩みは合わない。

それゆえ干支紀日は、商代以来二千余年、一度も途切れず、**世界で最も長く連続して用いられた日数の体系**である。だからこそ「逆に」精密な日数の計数器として使える——**一つのアンカーの日を定めれば、列全体が一意に定まる**。

## フィールド

| フィールド | 意味 |
|:---|:---|
| `date` | 太陽暦の日付 `YYYY-MM-DD` |
| `year` / `month` / `day` | 年月日の成分 |
| `weekday` | 曜日。**1＝月曜 … 7＝日曜**（ISO 8601） |
| `jdn` | ユリウス日数（整数、当日の正午に対応） |
| `ganzhi_day` | 日の干支。例「甲子」 |
| `ganzhi_index_1_60` | 干支の番号。**1＝甲子 … 60＝癸亥** |
| `xun` | 属する旬。例「甲子旬」 |
| `solar_term` | その日の属する節気（直近に交じた節気） |
| `solar_term_month_branch` | 節気月（月建）の地支。十二**節**で分ける |
| `next_term` / `next_term_datetime` | 次の節気の名と<ruby>交節時刻<rt>こうせつじこく</rt></ruby>（北京時間） |

**`solar_term_month_branch` について**：十二の**節**（立春・驚蟄・清明・立夏・芒種・小暑・立秋・白露・寒露・立冬・大雪・小寒）によってのみ分け、立春から寅月とする。**年干には関わらず、五虎遁などのいかなる推演も行わない**——これは「節気で分けた月」という暦法の構造そのものである。

## 整列アンカー

**1949-10-01 ＝ 甲子日。**

出所は三つとも一致する：百度百科「甲子日」の項は「中華人民共和国の成立日（1949年10月1日）がすなわち甲子日である」と明記し、複数の万年暦サイトの照会結果も一致し、よくある八字の教材の作例もその日を甲子日とする。

これをアンカーに選んだ理由：現代にあり、**暦の換算にまつわる曖昧さを一切伴わない**。

|:---|:---:|:---:|:---|
| 1590-12-22 | 甲子 | 甲子 | 一致 |
| 1861-11-11 | 甲子 | 甲子 | 一致 |
| **1949-10-01** | 甲子 | 甲子 | **整列アンカー** |
| 2025-12-21 | 甲子 | 甲子 | 一致 |

### 一件ずつの説明

**1. 古典のアンカーは自己整合的である——これが本表で最も強い検証である。**

『春秋』隠公三年の「**二月己巳、日に食あり**」は、日付を明記した中国の典籍で最初の日食記録である。そのユリウス暦での逆算日付は**紀元前 720 年 2 月 22 日**であり、本表が独立に数えると **己巳** で、文献と完全に一致する。

このアンカーと整列アンカーは **2,669 年**隔たっており、両者が自己整合的であることは、「六十日の循環が春秋以来途切れず続いた」という前提が成り立つことを示す。

> ⚠ **再計算の際は紀年法に必ず注意**：紀元前 720 年は**天文学的紀年 −719** に対応する（紀元前 1 年＝天文学的紀年 0、紀元 0 年は無い）。−720 として数えると、日付が**366 日**ずれ、**干支が 6 位**ずれる——日の干支は **己巳** から **癸亥** に変わり、「古籍と推算が合わない」と誤判定する。**これはきわめて踏みやすい穴である。**

**2. 一つの出所に誤りがあり、正直に注記した。**

公開資料の中の「1965-12-22 は甲子日」という説を、本表は**庚戌**と推算する。1965 年 12 月には甲子日が無い（その月で最も近い甲子は 1966-01-05）。**本表はこの一条のためにアンカーを動かしていない**——現代のアンカー 4 つのうち 4 つが一致し、古典アンカーも自己整合的であり、整列アンカーに誤りが無いことを支えるに足る。

## 暦の切り替え

1582-10-15 からグレゴリオ暦を用い、それ以前はユリウス暦を逆算する。**本データセットは 1900 年以降を覆うので、この切り替えには関わらない**。生成器はこの規則を実装済みで、より早い年へ拡張しやすい。

## A1 との関係

`solar_term` フィールドは **A1 二十四節気交節時刻データセット**から結合される。**本表を使うときは A1 も併せて引用することを勧める**。節気の境界の精度が `solar_term` と `solar_term_month_branch` の正しさを直接決めるからである。

**境界の扱い（踏みやすい一点）**：本表の最初の 5 日（1900-01-01 から 01-05）は 1900 年の小寒より前にあり、その属する節気は**1899 年の冬至**でなければならない。したがって生成時には A1 の主表のほかに、A1 の `data/preceding_boundary.csv` も読み込む必要がある——さもないとこの 5 日が 1900 年の小寒に誤って帰属され、月建が「丑」と誤記される（正しくは「子」）。
